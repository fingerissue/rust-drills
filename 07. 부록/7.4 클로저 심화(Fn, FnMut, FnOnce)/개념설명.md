# 7.4 클로저 심화 (Fn, FnMut, FnOnce, move)

> 4장에서 클로저 자체(`|x| x * x` 같은 문법)는 다뤘는데, "클로저가 캡처한 변수를 어떻게
> 다루느냐"에 따라 나뉘는 세 가지 트레잇(Fn/FnMut/FnOnce)은 안 다뤘었다. 실무 코드에서
> 제네릭 함수가 클로저를 받을 때 이 셋 중 뭘 써야 할지 헷갈리는 경우가 많아서 정리한다.

## 1. 세 트레잇의 차이

| 트레잇 | 캡처한 변수를... | 호출 횟수 |
|---|---|---|
| `Fn` | 읽기만 함 (`&self`) | 여러 번 |
| `FnMut` | 바꿈 (`&mut self`) | 여러 번 |
| `FnOnce` | 소유권을 가져가버림 (`self`) | 딱 한 번 |

모든 클로저는 최소 `FnOnce`는 구현한다. 캡처한 걸 안 바꾸면 `FnMut`도 구현하고,
아예 안 바꾸고 참조만 하면 `Fn`까지 구현한다. (즉 `Fn` ⊂ `FnMut` ⊂ `FnOnce` 관계)

```rust
let x = 5;
let read_only = || println!("{x}");        // Fn

let mut count = 0;
let mutate = || { count += 1; };           // FnMut (Fn은 아님 - 내부를 바꾸니까)

let s = String::from("hi");
let consume = move || s;                   // FnOnce (s의 소유권을 가져가서 반환하니까 한 번만 호출 가능)
```

## 2. 제네릭 함수에서 뭘 받아야 하나

함수가 클로저를 몇 번 호출할 건지, 클로저가 뭘 캡처하는지에 따라 트레잇 바운드를 고른다.

```rust
fn call_twice<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 {
    f(f(x)) // 두 번 호출하려면 Fn 이상이어야 함 (FnOnce면 두 번 못 부름)
}
```

**바운드는 최대한 느슨하게** 잡는 게 좋다 — `Fn`만 받아도 되는데 `FnMut`을 요구하면,
읽기 전용 클로저(`Fn`)를 넘기고 싶은 호출자를 불필요하게 막는 꼴이 된다.

## 3. move 키워드

클로저는 기본적으로 바깥 변수를 "필요한 만큼만" 캡처한다 (읽기만 하면 참조로).
`move`를 붙이면 **강제로 소유권을 가져가게** 만든다.

```rust
fn make_adder(n: i32) -> impl Fn(i32) -> i32 {
    move |x| x + n // move 없으면 n의 참조를 캡처하는데,
                   // 함수가 끝나면 n이 사라지므로 참조가 무효해진다 -> 컴파일 에러
}
```

**규칙**: 클로저를 함수 밖으로 반환하거나 다른 스레드로 넘길 때는 거의 항상 `move`가 필요하다.
(5.4에서 `thread::spawn(move || ...)`으로 이미 써봤을 것이다)

## 4. 클로저를 저장/반환하기 - `impl Fn` vs `Box<dyn Fn>`

- 함수를 반환할 때 **구체 타입 하나만** 반환하면 `impl Fn(...) -> ...` 로 충분하다 (정적 디스패치)
- 상황에 따라 **서로 다른 클로저**를 반환해야 하면 `Box<dyn Fn(...) -> ...>` 가 필요하다 (동적 디스패치,
  4.4의 `Box<dyn Trait>`와 똑같은 원리 — 클로저도 사실 트레잇을 구현한 값일 뿐이다)

```rust
fn choose_operation(op: &str) -> Box<dyn Fn(i32, i32) -> i32> {
    match op {
        "+" => Box::new(|a, b| a + b),
        "*" => Box::new(|a, b| a * b),
        _ => Box::new(|_, _| 0),
    }
}
```
`match`의 각 분기가 서로 다른(익명) 클로저 타입이라서 `impl Fn`으로는 못 쓰고 `Box<dyn Fn>`으로 감싸야 한다.
