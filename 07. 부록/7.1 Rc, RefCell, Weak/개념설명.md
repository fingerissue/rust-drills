# 7.1 Rc<T>, RefCell<T>, Weak<T>

> 책 목차엔 없지만, 트리/그래프 같은 구조를 다루려면 사실상 필수인 개념들.
> 4.6에서 다룬 `Box<T>`, 5.4에서 다룬 `Arc<Mutex<T>>`의 연장선이다.

## 왜 필요한가

`Box<T>`는 "소유자가 딱 하나"인 경우만 커버한다. 근데 이런 상황엔 안 맞는다:
- 트리에서 자식이 부모를 가리켜야 함 (부모는 여러 자식을 갖고, 자식도 부모를 가짐)
- 그래프에서 노드 여러 개가 서로를 참조

이런 "소유자가 여럿"인 상황을 위한 게 `Rc<T>`고, 거기에 "불변 참조인데도 값을 바꿔야 하는" 상황을 위한 게 `RefCell<T>`다.

## 1. Rc\<T\> - Reference Counted (참조 카운트 공유 소유권)

```rust
use std::rc::Rc;

let a = Rc::new(5);
let b = Rc::clone(&a); // 데이터를 복사하는 게 아니라 참조 카운트만 +1
println!("{}", Rc::strong_count(&a)); // 2
```

`clone()`을 불러도 안의 데이터(`5`)는 복사되지 않는다. 그냥 "몇 명이 이 데이터를 보고 있는지"
카운트만 늘어난다. 마지막 Rc가 drop되면(카운트가 0이 되면) 그때 데이터가 해제된다.

**주의**: `Rc`는 스레드 안전하지 않다. 여러 스레드에서 공유하려면 5.4에서 다룬 `Arc<T>`를 써야 한다.
(`Rc` = 싱글스레드용, `Arc` = 멀티스레드용. 나머지는 거의 같은 API)

## 2. RefCell\<T\> - 내부 가변성 (Interior Mutability)

Rust의 대여 규칙(가변 참조는 동시에 하나만)은 보통 **컴파일 타임**에 검사된다. 근데 `RefCell<T>`는
이 검사를 **런타임**으로 미룬다. 그래서 `&self`(불변 참조)만 갖고 있어도 내부 값을 바꿀 수 있다.

```rust
use std::cell::RefCell;

let cell = RefCell::new(5);
*cell.borrow_mut() += 1;      // 가변 대여 (런타임에 검사)
println!("{}", cell.borrow()); // 6, 불변 대여
```

`borrow()`/`borrow_mut()`를 동시에 잘못 겹쳐서 부르면 컴파일 에러가 아니라 **런타임 패닉**이 난다.
그래서 RefCell은 "꼭 필요할 때만" 쓰는 게 맞다 — 컴파일 타임 검사를 포기하는 대가가 있으니까.

## 3. Rc\<RefCell\<T\>\> 조합

이 둘을 합치면 "여러 곳에서 공유하면서 다 같이 수정 가능한 데이터"가 된다. 실무에서 아주 흔한 조합.

```rust
use std::rc::Rc;
use std::cell::RefCell;

let shared = Rc::new(RefCell::new(0));
let shared2 = Rc::clone(&shared);

*shared.borrow_mut() += 1;
*shared2.borrow_mut() += 1;
println!("{}", shared.borrow()); // 2 - 같은 데이터를 보고 있음
```

## 4. Weak\<T\> - 순환 참조 방지

부모가 자식을 `Rc`로 갖고, 자식도 부모를 `Rc`로 가지면 **순환 참조**가 생겨서 참조 카운트가 절대
0이 안 되고 메모리가 샌다. 그래서 "위 방향"(자식 -> 부모)은 `Weak<T>`(약한 참조)로 잡는다.

```rust
use std::rc::{Rc, Weak};

let parent = Rc::new(5);
let weak_ref: Weak<i32> = Rc::downgrade(&parent);

// 약한 참조는 원본이 살아있는지 보장 못하므로 upgrade()로 Option을 받아야 함
match weak_ref.upgrade() {
    Some(p) => println!("아직 살아있음: {}", p),
    None => println!("이미 사라짐"),
}
```

**규칙**: "소유"하는 방향(부모->자식)은 `Rc`, "그냥 참조만 하는" 방향(자식->부모)은 `Weak`.

## 5. 언제 뭘 쓰나 요약

| 상황 | 타입 |
|---|---|
| 소유자 하나, 힙에 저장 | `Box<T>` |
| 소유자 여럿(싱글스레드) | `Rc<T>` |
| 소유자 여럿(멀티스레드) | `Arc<T>` (5.4 참고) |
| 불변 참조로도 값 변경 필요 | `RefCell<T>` (싱글스레드) / `Mutex<T>` (멀티스레드) |
| 순환 참조 방지 (역방향 참조) | `Weak<T>` |
