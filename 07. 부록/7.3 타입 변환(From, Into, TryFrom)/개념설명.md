# 7.3 타입 변환 (From, Into, TryFrom, TryInto)

> 다른 사람 코드 읽다 보면 `.into()`, `String::from(x)` 이런 게 정말 많이 보인다.
> 알아두면 남의 코드 읽기가 훨씬 편해지는 관용구.

## 1. From - "이 타입에서 이렇게 변환할 수 있다" 선언

```rust
struct Celsius(f64);
struct Fahrenheit(f64);

impl From<Celsius> for Fahrenheit {
    fn from(c: Celsius) -> Self {
        Fahrenheit(c.0 * 9.0 / 5.0 + 32.0)
    }
}

let f = Fahrenheit::from(Celsius(100.0)); // 212.0
```

## 2. Into는 공짜로 딸려온다

`From<A> for B`를 구현하면, Rust가 자동으로 `Into<B> for A`도 만들어준다. 그래서 `.into()`가 가능해진다.

```rust
let c = Celsius(0.0);
let f: Fahrenheit = c.into(); // From을 뒤집어서 자동 생성된 것
```

**규칙**: `From`을 구현하고, 호출할 땐 편한 대로 `Type::from(x)` 또는 `x.into()`를 쓰면 된다.
(`into()`는 반환 타입을 문맥에서 추론해야 해서, 위처럼 타입 명시가 필요한 경우가 많다)

## 3. TryFrom / TryInto - 실패할 수도 있는 변환

`From`은 "항상 성공하는" 변환에만 써야 한다. 실패 가능성이 있으면(범위 초과, 파싱 실패 등) `TryFrom`을 쓴다.

```rust
struct Percentage(u8);

impl TryFrom<i32> for Percentage {
    type Error = String;
    fn try_from(value: i32) -> Result<Self, Self::Error> {
        if (0..=100).contains(&value) {
            Ok(Percentage(value as u8))
        } else {
            Err(format!("{value}는 범위 밖"))
        }
    }
}

let p = Percentage::try_from(150); // Err("150는 범위 밖")
```

`TryFrom`을 구현하면 `TryInto`도 자동으로 딸려온다 (`From`/`Into` 관계와 똑같다).

## 4. 함수 파라미터에서 `impl Into<T>` 쓰기

호출하는 쪽 코드가 훨씬 유연해진다 — 여러 타입을 다 받아줄 수 있음.

```rust
fn describe_id(id: impl Into<Id>) -> String {
    let id: Id = id.into();
    format!("발급된 ID: {}", id.0)
}

describe_id(42);      // i32 -> Id로 자동 변환
describe_id("abc");   // &str -> Id로 자동 변환
```

## 5. 실무에서 자주 보이는 곳

- 에러 타입 변환: `?` 연산자는 내부적으로 `From`을 써서 에러 타입을 자동 변환한다
  (그래서 `fn f() -> Result<T, MyError>` 안에서 `some_io_result?`가 되려면
  `impl From<io::Error> for MyError`가 있어야 함)
- `String::from("abc")`, `"abc".to_string()`, `"abc".into()` — 셋 다 결국 같은 매커니즘
- 라이브러리 API 설계: 파라미터를 구체 타입 대신 `impl Into<T>`로 받아서 사용자 편의성을 높임
