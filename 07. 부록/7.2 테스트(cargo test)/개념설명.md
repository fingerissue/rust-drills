# 7.2 테스트 (#[test], cargo test)

> 사실 이게 부록 중에서 제일 중요하다. 지금까지 이 레포의 모든 문제는
> `main()` 안에 `assert_eq!`를 박아놓고 실행하는 방식이었는데, 실제 Rust 프로젝트에서는
> `#[test]` 함수 + `cargo test`가 표준이다.

## 1. 가장 기본 형태

```rust
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

#[cfg(test)]
mod tests {
    use super::*; // 바깥 모듈(add 함수)을 가져옴

    #[test]
    fn test_add() {
        assert_eq!(add(2, 3), 5);
    }
}
```

`#[cfg(test)]`는 "테스트 모드로 컴파일할 때만 이 코드를 포함해라"는 뜻이다. 그래서 평소
빌드(`cargo build`)에는 테스트 코드가 아예 안 들어가고, `cargo test`를 돌릴 때만 컴파일된다.

이 레포에서 `problem.rs`/`answer.rs`는 Cargo 프로젝트가 아니라 단일 파일이라, `cargo test` 대신
`rustc --test` 로 같은 효과를 낸다:
```bash
rustc --test answer.rs -o answer_test
./answer_test
```

## 2. cargo 프로젝트라면

```bash
cargo test                  # 전체 테스트 실행
cargo test test_add         # 이름에 test_add가 포함된 테스트만 실행
cargo test -- --ignored     # #[ignore] 붙은 것만 실행
cargo test -- --include-ignored  # ignore 여부 상관없이 전부 실행
```

## 3. #[should_panic] - "이 코드는 패닉나야 정상"인 걸 테스트

```rust
#[test]
#[should_panic(expected = "0으로 나눌 수 없음")]
fn test_divide_by_zero_panics() {
    divide(1, 0); // 이 안에서 panic!("0으로 나눌 수 없음")이 나야 테스트 통과
}
```
`expected`에 넣은 문자열이 실제 패닉 메시지에 포함돼있어야 통과한다. (없으면 그냥 "패닉이 나기만 하면" 통과)

## 4. #[ignore] - 평소엔 건너뛰기

느리거나(네트워크 호출 등) 특수 조건에서만 도는 테스트에 붙인다. 평소 `cargo test`에서는
"ignored"로 표시되고 스킵되며, `--ignored` 또는 `--include-ignored` 옵션을 줘야 실행된다.

```rust
#[test]
#[ignore]
fn test_slow_case() {
    // 오래 걸리는 테스트...
}
```

## 5. 왜 이게 중요한가

- 함수마다 **개별로** 통과/실패가 보인다 (지금 이 레포의 `main()`+`assert_eq!` 방식은 하나 막히면
  뒤에 있는 문제들이 아예 실행조차 안 됨)
- 실제 오픈소스/회사 코드는 거의 다 이 방식으로 테스트를 짠다. `cargo test`가 안 도는 프로젝트는
  거의 없다고 봐도 됨.
- CI(이 레포의 GitHub Actions 같은 것)에서 자동으로 돌리기도 이 방식이 훨씬 표준적이다.
