# 6.5 웹 어셈블리 (WASM)

## 왜 코드 문제가 없나?
wasm32 타겟 컴파일 + 브라우저(또는 wasmtime) 실행 환경이 이 컨테이너에는 없어서
자동 검증이 불가능하다. 대신 핵심 개념과, 브라우저 유무와 상관없이 테스트 가능한
"로직 부분"만 정리한다.

## 핵심 개념

### 1. WASM은 "순수 로직"과 "브라우저 연결부"를 분리해서 짜는 게 핵심
6.4에서 만든 계산기 로직 같은 순수 함수는 wasm으로 컴파일해도 그대로 재사용 가능하다.
`wasm-bindgen`이 하는 일은 이 순수 로직을 JS에서 호출 가능하게 감싸주는 것뿐이다.

```rust
use wasm_bindgen::prelude::*;

// 순수 로직 - 네이티브에서도, wasm에서도 동일하게 동작하고 테스트 가능
pub fn calculate(a: f64, b: f64, op: &str) -> f64 {
    match op {
        "+" => a + b,
        "-" => a - b,
        "*" => a * b,
        "/" => a / b,
        _ => 0.0,
    }
}

// 브라우저 JS에서 호출할 진입점 - 순수 로직을 감싸기만 함
#[wasm_bindgen]
pub fn calculate_js(a: f64, b: f64, op: &str) -> f64 {
    calculate(a, b, op)
}
```

`calculate` 함수는 일반 Rust 테스트로 바로 검증 가능하다:
```rust
fn main() {
    assert_eq!(calculate(3.0, 4.0, "+"), 7.0);
    assert_eq!(calculate(10.0, 2.0, "/"), 5.0);
    println!("계산기 로직 테스트 통과");
}
```

### 2. 개발 환경 (로컬 PC 기준)
```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
wasm-pack build --target web
```

### 3. 제약사항
- 파일시스템, 스레드, 일부 네트워크 기능에 제약이 있음 (브라우저 샌드박스)
- 시스템 폰트 등 OS 리소스에 직접 접근 불가 -> 폰트를 데이터로 내장하거나 웹폰트 사용
- DOM 조작은 `web-sys`/`js-sys` 크레이트로 가능하지만 JS보다 번거로움

### 4. 참고
- 6.4에서 만든 계산기를 그대로 wasm으로 빌드해서 브라우저에서 돌리는 게 이 챕터의 목표.
- 로컬 환경에서 `wasm-pack build` 후 `index.html`에 붙여서 직접 확인해보는 걸 추천.
